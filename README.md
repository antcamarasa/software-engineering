# Software engineering

Mon parcours d'autoformation en informatique fondamentale, construit sur une seule idée :
 
> **Short cut makes long delay.**
 
Les frameworks, je les apprends au travail. Ici, je construis ce que les frameworks cachent : les structures de données, le langage C, le réseau, l'os.

## Règles
 
1. **Un bloc à la fois.** Je termine le bloc en cours avant d'ouvrir le suivant.
2. **Une ressource par bloc.** Pas de liste de 50 liens. Un seul livre, utilisé pour sa pratique.
3. **Le code d'abord.** Chaque bloc se termine par ce que j'ai construit moi-même, pas par des notes.
4. **Condition de sortie.** Un bloc est terminé quand sa condition de sortie est remplie. Ni avant, ni après.

## Les blocs
 
### 1. Structures de données et algorithmes — Java
 
**Pourquoi :** la base de tout. Choisir une structure, raisonner en complexité, écrire du vrai code orienté objet (ADT → classe abstraite → implémentations).
 
**Condition de sortie :** je recode chaque structure de mémoire et je résous seul les exercices de chaque chapitre.
 
### 2. Langage C
 
**Pourquoi :** le langage de tous les blocs suivants. Pointeurs, mémoire, structs, et ce que sont vraiment un buffer et un stream.
 
**Périmètre :** le livre entier
 
### 3. Programmation réseau
 
**Pourquoi :** un back-end, c'est un programme qui parle à d'autres programmes à travers le réseau. Sockets, TCP, UDP, DNS, HTTP, TLS.
 
**Projet :** La plateforme proposait en première année, un serveur de chat type Discord en C. Ce projet est impossible a faire pour un débutant. Par contre le sujet est extrêmement intéressant.
 
### 4. Système d'exploitation
 
**Pourquoi :** ce que l'OS fait pour mes programmes : processus, signaux, mémoire virtuelle, malloc, threads.
